# Testing

## Automated (no extra hardware)

```powershell
cd D:\nexashare
npm test
```

Coverage designed in-repo:

- Path traversal and reserved names
- Transfer state transitions
- Discovery/control schema validation and size limits
- Pairing success, wrong code, consumed session
- Unauthenticated PUT rejected
- Loopback paired transfer with SHA-256 of generated bytes
- Declined transfer path

## Integration layout

Two `NexaEngine` instances bind `127.0.0.1` with `port: 0` and `enableDiscovery: false`. They pair, then stream a temp file over TLS.
